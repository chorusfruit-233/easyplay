# Draughts 通用 AI

八种已有规则均可从跳棋首页的「人机对弈」进入。开局选择黑方/白方和
初级、中级、高级；每种规则仍按自身先手规定行棋。棋盘将玩家棋子放在下方。

也可从「AI 对抗」进入两名 AI 自动对弈的观战模式，独立设置双方难度，支持暂停、单步、悔棋与存档恢复，详见 [AI 观战说明](AI_DUEL.md)。

AI 使用 Dart 实现，无需模型下载或外部引擎，Android 与 Web 共用搜索核心。
Negamax、Alpha-Beta 剪枝和迭代加深配合吃子/升王走法排序；中、高级的叶节点遇到强制
吃子时继续搜索，中级最多延伸六手、高级十手完整着法。评分考虑子力、升王进度和中心位置，
短王与飞王使用不同权重。当前定位为休闲陪练，难度尚未标定为 Elo。

| 难度 | 最大深度 | 节点上限 | 思考时间预算 |
| --- | ---: | ---: | ---: |
| 初级 | 1 | 120 | 100 ms |
| 中级 | 5 | 4000 | 800 ms |
| 高级 | 10 | 32000 | 2400 ms |

高级增加PVS主变化搜索、杀手走法与历史启发排序，优先验证前面找到的有希望的变例。窄窗口发现更好走法时重新搜索，确认同分后才参与变化选择。高级的局面评分还考虑行动空间、邻近友子支援、后排防守与升王进度；子力占优时推动王靠近对手，帮助残局转化。斜走和土耳其直走规则分别使用对应方向。

初级面向入门练习：不延伸搜索对手的强制吃子，75% 的回合在全部合法走法中
等概率随机选择，其余回合按一手评分选招，因此会漏看送子和组合。强制吃子、
最大吃子、升王与完整连续吃子仍遵循各变体规则；中、高级在完整搜索中同等评分的走法间随机选择，不扩大评分容差。
已保存的初级对局恢复后也使用此策略，难度标识与存档格式保持兼容。

搜索预算耗尽时保留最近一次完成迭代的走法；来不及完成第一层时保留合法候选。
初级随后应用上述随机选招策略，中、高级可在最近一次完整迭代的同分走法中选择；根节点搜索会区分实值与剪枝边界，避免把实际较差的走法当成同分。第一层尚未完成时不作同分随机选择。
深度单位是一整手，包含全部连续吃子。时间预算会在节点边界检查，一次复杂
合法走法生成仍可能超出预算；这些数值不是设备上的严格响应时间保证。

搜索使用 `DraughtsSession.fork()`，共享不可变棋盘、保留完整和棋历史，独立维护
分支状态。AI 返回值通过正式 Session 再验证，不修改联机模式的规则或事件。
每 16 个节点让出事件循环，使 Android/Web 都能处理界面输入和取消请求。

玩家只能操作自己的回合。悔棋撤销到玩家上次落子前；认输归属玩家，后台暂停、
退出页面和悔棋都取消旧任务，返回前台时重新搜索。提交前检查任务代号及局面
revision，防止旧结果在新局面落子。自动和棋按规则核心判断；人机模式暂不提供
协商提和。

自动存档包含人机模式、执棋方、难度和完整对局。最近对局恢复后继续人机模式，
保存的着法重建悔棋历史。旧版本地/联机存档仍可读取，PDN 导出仍保留完整着法。

相关测试在 `test/draughts/ai_test.dart`、`ai_page_test.dart` 和 `storage_test.dart`，
覆盖八种规则、完整三段吃子、避免直接送子、预算、取消、局面隔离、和棋历史、
存档恢复、执棋方与难度选择、悔棋和应用生命周期。

`advanced_ai_test.dart` 另验证八种规则的高级预算与合法性，以及主变化搜索取消。在国际跳棋初始局面、1600节点预算下，高级完成4层搜索，冻结的旧高级仅完成3层。新旧高级的AOT换先对照命令见 [五子棋AI说明](GOMOKU_AI.md)。
