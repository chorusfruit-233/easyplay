# Draughts 通用 AI

八种已有规则均可从跳棋首页的「人机对弈」进入。开局选择黑方/白方和
初级、中级、高级；每种规则仍按自身先手规定行棋。棋盘将玩家棋子放在下方。

AI 使用 Dart 实现，无需模型下载或外部引擎，Android 与 Web 共用搜索核心。
Negamax、Alpha-Beta 剪枝和迭代加深配合吃子/升王走法排序；叶节点遇到强制
吃子时继续搜索，最多延伸六手完整着法。评分考虑子力、升王进度和中心位置，
短王与飞王使用不同权重。当前定位为休闲陪练，难度尚未标定为 Elo。

| 难度 | 最大深度 | 节点上限 | 思考时间预算 |
| --- | ---: | ---: | ---: |
| 初级 | 3 | 600 | 250 ms |
| 中级 | 5 | 4000 | 800 ms |
| 高级 | 8 | 16000 | 1800 ms |

任一预算耗尽就返回最近一次完成迭代的走法；来不及完成第一层时返回合法候选。
深度单位是一整手，包含全部连续吃子。时间预算会在节点边界检查，一次复杂
合法走法生成仍可能超出预算；这些数值不是设备上的严格响应时间保证。

搜索使用 `DraughtsSession.fork()`，共享不可变棋盘、保留完整和棋历史，独立维护
分支状态。AI 返回值通过正式 Session 再验证，不修改联机模式的规则或事件。
每 16 个节点让出事件循环，使 Android/Web 都能处理界面输入和取消请求。

玩家只能操作自己的回合。悔棋撤销到玩家上次落子前；认输归属玩家，后台暂停、
退出页面和悔棋都取消旧任务，返回前台时重新搜索。提交前检查任务代号及局面
revision，防止旧结果在新局面落子。自动和棋按规则核心判断；人机模式暂不提供
协商提和。

自动存档包含人机模式、执棋方、难度和完整对局。最近对局恢复后继续人机模式，
保存的着法重建悔棋历史。旧版本地/联机存档仍可读取，PDN 导出仍保留完整着法。

相关测试在 `test/draughts/ai_test.dart`、`ai_page_test.dart` 和 `storage_test.dart`，
覆盖八种规则、完整三段吃子、避免直接送子、预算、取消、局面隔离、和棋历史、
存档恢复、执棋方与难度选择、悔棋和应用生命周期。
